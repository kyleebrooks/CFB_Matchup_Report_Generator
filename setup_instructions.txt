AFPLNA AI Report Service — Full Setup on DigitalOcean

This guide bootstraps a brand-new Ubuntu Droplet and deploys the Flask/Gunicorn/Nginx service that generates and serves matchup PDFs, runs scheduled Rotowire updates, and exposes the /generate-report and /get-report endpoints.

8) Environment variables

API KEYS — where they live

The app reads API keys from the MySQL API_KEYS table first, then falls back to the
environment. OpenRouter is the ONLY LLM provider; there is no direct OpenAI call left.

  Preferred (matches the existing key store):
    INSERT INTO API_KEYS (`API_NAME`, `KEY`) VALUES ('openrouter', 'sk-or-v1-...');

  Fallback (env file below):
    OPENROUTER_API_KEY='sk-or-v1-...'

Verify after deploy:
    curl -sS "http://localhost/health/llm?api_key=YOUR_SERVICE_API_KEY" | jq

That endpoint resolves the key and pings both models (research + report). Any legacy
'openai' row in API_KEYS is now unused and can be removed.

Create /etc/afplna.env:

sudo tee /etc/afplna.env >/dev/null << 'EOF'
# API auth for clients (what your frontend sends)
SERVICE_API_KEY=REPLACE_WITH_A_STRONG_RANDOM_STRING

# MySQL (GoDaddy) connection for kdogg4207
DB_HOST=p3nlmysql149plsk.secureserver.net
DB_USER=kdogg4207
DB_NAME=kdogg4207
DB_PASSWORD=REPLACE_WITH_YOUR_DB_PASSWORD

# Optional if keys are not stored in DB
# CFBD_API_KEY=
# OPENROUTER_API_KEY=   # single gateway for ALL LLM calls (research + report)
# WKHTMLTOPDF_PATH=/usr/bin/wkhtmltopdf

# Multi-tenant API (/v1). Whoever holds this can mint accounts - keep it secret.
ADMIN_API_KEY=REPLACE_WITH_A_LONG_RANDOM_STRING

# Optional model / behavior overrides (defaults shown)
# OPENROUTER_RESEARCH_MODEL=deepseek/deepseek-v4-flash
# OPENROUTER_REPORT_MODEL=moonshotai/kimi-k3
# OPENROUTER_SEARCH_ENGINE=exa         # exa | native | (blank = OpenRouter picks)
#   NOTE: DeepSeek has no native web search - leave this on 'exa' unless the
#   research model is switched to an OpenAI/Anthropic/Google/xAI model.
# OPENROUTER_SEARCH_MAX_RESULTS=5      # Exa bills ~$4/1000 results
# WATERMARKS_DIR=/opt/afplna/watermarks
# RESEARCH_TIMEOUT=240
# REPORT_TIMEOUT=420
# REPORT_MAX_TOKENS=96000   # covers reasoning tokens AND the report; too low = empty output
# REPORT_EFFORT=high        # low | medium | high
EOF

sudo chmod 600 /etc/afplna.env
sudo chown root:root /etc/afplna.env
sudo sed -i 's/\r$//' /etc/afplna.env

9) Systemd service (Gunicorn)

Create unit:

sudo tee /etc/systemd/system/afplna.service >/dev/null << 'EOF'
[Unit]
Description=AFPLNA Flask service (Gunicorn)
After=network.target

[Service]
User=deploy
Group=www-data
WorkingDirectory=/opt/afplna
EnvironmentFile=/etc/afplna.env
# systemd does not set HOME, and matplotlib needs a writable cache dir. The app picks a
# temp dir automatically, but setting this explicitly keeps the cache warm across restarts.
Environment=MPLCONFIGDIR=/opt/afplna/.mplcache
ExecStart=/opt/afplna/venv/bin/gunicorn "app:app" --bind 127.0.0.1:5000 --workers 1 --threads 8 --timeout 900 --graceful-timeout 900
Restart=always
RestartSec=3
TimeoutStartSec=60

[Install]
WantedBy=multi-user.target
EOF

sudo -u deploy mkdir -p /opt/afplna/.mplcache

sudo systemctl daemon-reload
sudo systemctl enable --now afplna
sudo systemctl status afplna --no-pager -l

10) Nginx reverse proxy

Create server block:

sudo tee /etc/nginx/sites-available/afplna >/dev/null << 'EOF'
server {
    listen 80;
    server_name _;

    proxy_read_timeout 900s;
    client_max_body_size 16m;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host               $host;
        proxy_set_header X-Real-IP          $remote_addr;
        proxy_set_header X-Forwarded-For    $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto  $scheme;
    }
}
EOF

sudo ln -s /etc/nginx/sites-available/afplna /etc/nginx/sites-enabled/afplna
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx

11) HTTPS (optional, recommended)

Point DNS of api.yourdomain.com → Droplet IP, then:

sudo sed -i 's/server_name _;/server_name api.yourdomain.com;/' /etc/nginx/sites-available/afplna
sudo nginx -t && sudo systemctl reload nginx
sudo apt -y install certbot python3-certbot-nginx
sudo certbot --nginx -d api.yourdomain.com

12) CORS

The app implements CORS in `app.py` with a custom `@app.after_request`
handler—**do not** add Flask-Cors. Make sure your server is running the
latest code so this handler is active.

Edit `ALLOWED_ORIGINS` in the code to list every allowed domain
exactly. Include both HTTP and HTTPS and any `www` variations, for
example:

```
ALLOWED_ORIGINS = {
    "http://afplnapicks.com",
    "http://www.afplnapicks.com",
    "https://afplnapicks.com",
    "https://www.afplnapicks.com",
}
```

After saving changes, restart the service and verify startup logs for
errors:

```
sudo systemctl restart afplna
sudo systemctl status afplna --no-pager -l
```

Re-test the API from the browser and confirm the
`Access-Control-Allow-Origin` header matches the requesting origin.


13) Smoke tests

From the Droplet:

# Nginx → Gunicorn alive?
curl -I http://localhost/

# LLM connectivity (resolves the OpenRouter key, pings both models)
curl -sS "http://localhost/health/llm?api_key=YOUR_API_KEY" | jq

# Generate — returns 202 immediately with a job handle
curl -sS -X POST http://localhost/generate-report \
 -H 'Content-Type: application/json' \
 -d '{"api_key":"YOUR_API_KEY","home_full":"Georgia Bulldogs","away_full":"Marshall Thundering Herd","home_short":"Georgia","away_short":"Marshall"}' | jq

# Watch progress (state: queued -> running -> done | error)
watch -n5 'curl -sS "http://localhost/report-status?api_key=YOUR_API_KEY&home_team=Georgia&away_team=Marshall" | jq'

# Or block until finished instead of polling (caller owns the timeout)
curl -sS --max-time 900 -X POST "http://localhost/generate-report?wait=true" \
 -H 'Content-Type: application/json' \
 -d '{"api_key":"YOUR_API_KEY","home_full":"Georgia Bulldogs","away_full":"Marshall Thundering Herd","home_short":"Georgia","away_short":"Marshall"}' | jq

# Download
curl -L -o report.pdf "http://localhost/get-report?api_key=YOUR_API_KEY&home_team=Georgia&away_team=Marshall"

14) Frontend integration

On your PHP page (e.g., scoreboard.php):

scoreboard.php in this repo is the reference implementation — it already does all of
the below. If you are wiring another page, follow the same shape:

Generate → POST /generate-report. This returns 202 in milliseconds; it does NOT wait
for the report. Never keep the POST open for the duration of a build.

Progress → poll GET /report-status?api_key=...&home_team=...&away_team=... every ~4s.
Render state / percent / message as a progress bar. Stop polling when state becomes
"done" or "error"; surface the error text when it is "error".

Download → GET /get-report?api_key=...&home_team=...&away_team=....

On page load, call /report-status once and resume polling if a build is already
running — that way a refresh, or a build started in another tab, keeps showing live
progress instead of looking idle.

Because the previous PDF is only swapped out at the very end of a rebuild, Download
stays usable the whole time a regeneration is running.

15) Scheduler notes

APScheduler triggers the Rotowire/Bright collector at 9:00 and 18:00 (America/New_York) and upserts into the rotowire table.

Keep Gunicorn workers at 1 in the unit to avoid duplicate runs. The unit above is set
to --workers 1 --threads 8 for exactly this reason: report generation is I/O-bound on
API calls, so threads give concurrency without duplicating the scheduler.

Optional: add a debug route to trigger the job manually (remove after testing).

16) Logs & troubleshooting

FIRST STOP: 502 Bad Gateway from Nginx

502 means Gunicorn is not running — the app failed to START, so no request ever
reached it. This is always an import-time or environment problem, never a bug in a
route. Get the real error:

    sudo systemctl status afplna --no-pager -l | head -30
    sudo journalctl -u afplna -n 60 --no-pager -o cat

    # reproduce the import directly - this prints the actual traceback
    cd /opt/afplna && sudo -u deploy /opt/afplna/venv/bin/python -c "import app"

Most common causes:
  - Dependencies not reinstalled after a pull (matplotlib is the usual one):
        source /opt/afplna/venv/bin/activate && pip install -r /opt/afplna/requirements.txt
  - A .py file missing from /opt/afplna because rsync was skipped after git pull
  - Port 5000 already held by an old process:  sudo fuser -k 5000/tcp

Once it starts, confirm every dependency at once:

    curl -sS "http://localhost/health?api_key=YOUR_SERVICE_API_KEY" | jq

Debugging tip: do NOT pipe to jq while diagnosing. jq hides the response. A
"parse error: Invalid numeric literal at line 1, column 10" just means jq was handed
Flask's HTML 404 page. Use curl -i to see the status and raw body first:

    curl -sS -i "http://localhost/health?api_key=YOUR_SERVICE_API_KEY"

# Live app logs
journalctl -fu afplna -o cat

# Recent errors
journalctl -u afplna -n 200 --no-pager -o cat

# Nginx logs
tail -f /var/log/nginx/error.log
tail -f /var/log/nginx/access.log


Common issues:

Env file missing → ensure /etc/afplna.env exists and is referenced in unit.

Port 5000 in use → fuser -k 5000/tcp.

Gunicorn missing → install via requirements.

Module name mismatch → app.py must expose app; else change app:app to <module>:app.

wkhtmltopdf not found → install or set WKHTMLTOPDF_PATH.

DB access → whitelist Droplet IP on DB host; test with mysql -h ... -u ... -p.
